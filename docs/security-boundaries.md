# Security boundaries

The Digital Banking Experience Laboratory is an independent educational project, not a production banking application. Its examples teach interface and integration concepts without using or implying access to real financial systems.

## Non-negotiable data rules

- Do not use real member data, credentials, account numbers, or financial transactions.
- Do not connect examples to production authentication or production services.
- Fixture values must be synthetic and recognizable as test data. Names, identifiers, balances, timestamps, and workflows must remain obviously fictional.
- Sensitive internal identifiers must not appear in the member interface. A fixture may carry an internal test identifier to demonstrate that boundary, but the rendered interface should expose only an appropriate masked suffix.

Harbor Community Credit Union and all of its members and accounts are fictional. Secrets must never be committed, even for a fictional scenario.

## Claims this project does not make

The laboratory makes no claim of regulatory compliance, production readiness, or security certification. It makes no claim of knowledge about any financial institution's proprietary environment. In particular, it does not recreate or represent Langley Federal Credit Union's actual systems, vendors, architecture, data, internal procedures, or controls.

These boundaries are part of each lesson's definition of done, not optional disclaimers.
